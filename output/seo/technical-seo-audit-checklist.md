# Well Art — технический SEO-аудит сайта

Дата среза: 15 августа 2026 года  
Проверяемый сайт: https://mebel-showroom.vercel.app/  
Проект: Astro 6, TypeScript, статическая сборка (`output: "static"`), Vercel  
Текущая сборка: 60 статических страниц, включая 49 карточек товаров и 6 категорий

## Задача для проверяющего агента

Проведи технический SEO-аудит текущей production-версии и исходного кода. Не ограничивайся Lighthouse. Для каждого найденного пункта укажи:

1. URL или файл и строку, где обнаружена проблема.
2. Фактическое поведение и ожидаемое поведение.
3. Приоритет: `P0` — блокирует индексирование, `P1` — заметно влияет на поиск/скорость, `P2` — улучшение.
4. Способ проверки и доказательство: HTTP-ответ, HTML, скриншот, результат валидатора или измерение.
5. Конкретное исправление для Astro/Vercel.

Не предлагай генерировать страницы или факты, которые не подтверждены бизнесом. Цены, наличие, адрес, график, условия доставки и характеристики товаров считать изменяемыми данными.

## Что уже реализовано — проверить, а не предлагать с нуля

- Статическая генерация Astro без отдельного Node/SSR-процесса.
- Абсолютный `canonical` на каждой странице.
- `robots.txt` и XML sitemap через `@astrojs/sitemap`.
- Уникальные `title` и `description` формируются для основных типов страниц.
- Open Graph и Twitter Card.
- JSON-LD `FurnitureStore` на страницах сайта.
- JSON-LD `Product` и `BreadcrumbList` на товарных страницах.
- JSON-LD `ItemList` в каталоге и категориях.
- Реальные HTML-ссылки между главной, категориями и товарами.
- Атрибуты `width` и `height` у основных изображений.
- AVIF/JPEG и `srcset` для первого экрана главной.
- `loading="lazy"` у большинства изображений ниже первого экрана.
- Hero/LCP-изображение главной не ленивое и имеет `fetchpriority="high"`.
- Русский язык документа: `<html lang="ru">`.
- Страница 404, favicon, web manifest и базовая доступность навигации.

## 1. Доступность для роботов и индексирование — P0

- [ ] Все публичные URL отвечают `200`, удалённые — настоящим `404`, постоянные перенаправления — `301/308`; нет soft 404.
- [ ] Production не отдаёт `X-Robots-Tag: noindex` и в HTML нет случайного `<meta name="robots" content="noindex">`.
- [ ] `robots.txt` доступен с кодом `200`, не блокирует CSS, JS, изображения, каталог и товары.
- [ ] `sitemap-index.xml` доступен, валиден и содержит только канонические индексируемые URL с кодом `200`.
- [ ] В sitemap нет 404, редиректов, параметров поиска/фильтров и служебных страниц.
- [ ] URL из sitemap совпадают с реальным production-доменом и протоколом HTTPS.
- [ ] Проверить обе формы URL со слешем и без слеша. Должна оставаться одна каноническая версия без цепочек редиректов.
- [ ] HTTP, `www` и технические домены/алиасы перенаправляются на один выбранный домен.
- [ ] Параметры `/catalog?q=`, `?category=` и `?status=` не создают индексируемые дубли: canonical должен вести на `/catalog`.
- [ ] В Google Search Console и Яндекс Вебмастере нет массовых статусов «Просканировано, но не проиндексировано», дублей и ошибок sitemap.

## 2. Canonical, URL и дубли

- [ ] На каждой индексируемой странице ровно один абсолютный self-referencing canonical.
- [ ] Canonical отвечает `200`, не ведёт через редирект и не указывает на другую по смыслу страницу.
- [ ] Slug товара стабилен, читаем и уникален; смена slug сопровождается `301` со старого URL.
- [ ] Нет дублей `/index.html`, разных регистров, двойных слешей, URL с лишним расширением.
- [ ] Внутренние ссылки сразу ведут на финальный канонический URL.
- [ ] Карточки разных товаров с одной фотографией не считаются одним товаром: у них уникальны название, SKU, описание и URL.

## 3. Заголовки и метаданные

- [ ] На каждой странице один содержательный `<title>` и один `<meta name="description">`.
- [ ] Нет одинаковых title/description между товарами и категориями.
- [ ] Title начинается с главного смысла страницы, содержит бренд без переспама и не обрезается бессмысленно в выдаче.
- [ ] Description соответствует видимому контенту и не обещает неподтверждённые услуги, наличие или цены.
- [ ] На каждой странице один основной `h1`; порядок `h1 → h2 → h3` логичен.
- [ ] `og:title`, `og:description`, `og:url`, `og:image` и `twitter:*` совпадают со страницей.
- [ ] OG-изображения доступны роботам, имеют корректный MIME type и достаточный размер; для товара используется его собственная фотография.
- [ ] После подключения собственного домена обновлены `site` в `astro.config.mjs`, canonical, sitemap, robots и OG URL.

## 4. Структурированные данные JSON-LD

Проверить через Google Rich Results Test и Schema.org Validator. Сопоставлять JSON-LD с видимым пользователю контентом.

- [ ] JSON-LD является валидным JSON и не содержит ошибок типов/полей.
- [ ] `FurnitureStore`: одинаковые название, URL, телефон, адрес и часы работы на сайте, в 2ГИС и бизнес-профилях.
- [ ] Уточнить и при наличии добавить индекс, координаты `geo`, ссылку `hasMap`, ценовой диапазон и официальные профили — только после подтверждения.
- [ ] `Product`: уникальные `name`, `description`, `sku`, `image`, `category` и постоянный `@id`.
- [ ] `Offer` присутствует только при подтверждённой цене; `priceCurrency` = `RUB`, цена числовая, URL канонический.
- [ ] `availability` соответствует фактическому статусу. Не размечать `InStock`, если наличие только уточняется.
- [ ] Товары без цены могут не получить товарный rich result: проверить требования валидатора и не придумывать `Offer` ради прохождения теста.
- [ ] Старая цена не размечается как действующая. Если показывается скидка, определить корректную текущую цену и при необходимости `priceValidUntil`.
- [ ] `BreadcrumbList` совпадает с видимыми хлебными крошками и содержит правильный порядок URL.
- [ ] `ItemList` каталога и категорий содержит канонические URL реально показанных товаров.
- [ ] Нет конфликтующих сущностей магазина с разными `@id`.

## 5. Изображения, lazy-loading и медиаконтент

- [ ] Главное LCP-изображение каждой страницы не имеет `loading="lazy"`.
- [ ] Изображения ниже первого экрана используют `loading="lazy"` и по возможности `decoding="async"`.
- [ ] Не применять lazy-loading к логотипу/hero, если это задерживает первый экран.
- [ ] У всех изображений заданы реальные `width` и `height` либо `aspect-ratio`, чтобы исключить CLS.
- [ ] Для товарных фото добавить подходящие `srcset`/`sizes`, чтобы desktop не загружал и не растягивал маленькую картинку.
- [ ] Для тяжёлых JPEG подготовить WebP/AVIF с визуально приемлемым качеством и JPEG fallback.
- [ ] Проверить вес: hero, изображения категорий и карточек не должны передаваться заметно крупнее отображаемого размера.
- [ ] `alt` описывает конкретный предмет/сцену, не набит ключевыми словами и не повторяется бессмысленно.
- [ ] Декоративные и повторные thumbnail-изображения могут иметь пустой `alt`, если доступное имя уже есть у кнопки.
- [ ] Все файлы изображений возвращают корректный MIME type, долгое кеширование и не дают 404.
- [ ] Проверить визуальные JPEG-артефакты на широком desktop и Retina-экране.
- [ ] Составить таблицу повторов `товар → основное фото`. Для каждого отдельного товара назначить собственный главный кадр.

### Уже известные повторы, которые нужно убрать после получения дополнительных фото

- Стол Roma и стул Roma используют один кадр `roma-dining.jpg`.
- Стол Fugato и стул Dolmen используют один кадр `fugato-dining.jpg`.
- Стол Agua и стул Malta используют один кадр `agua-dining.jpg`.
- Туалетный столик Camaro и зеркало Camaro используют `camaro-dressing.jpg`.
- Кровать, тумба и шкаф Camaro используют `camaro-bedroom.jpg`.
- Туалетный столик Wagon и зеркало Wagon используют `wagon-dressing.jpg`.
- Парные товары Astor и Icon используют одинаковые наборы кадров в разном порядке.
- В галереях столика Wood и столика Bag есть общий интерьерный кадр с соседним товаром из той же публикации.

Это не техническая ошибка индексации, но снижает различимость карточек, доверие и качество поиска по изображениям.

## 6. Core Web Vitals и скорость

Проверять отдельно mobile и desktop, минимум главную, каталог, категорию и несколько товарных страниц.

- [ ] Полевые показатели на 75-м перцентиле: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1.
- [ ] Lighthouse/PageSpeed Insights запускать несколько раз и сохранять медианный результат.
- [ ] Определить фактический LCP-элемент на каждом шаблоне.
- [ ] Нет render-blocking ресурсов, которые можно безопасно отложить или встроить.
- [ ] Google Fonts не создают лишнюю задержку: проверить DNS/TLS, `font-display`, preload и целесообразность self-hosting WOFF2.
- [ ] JS каталога, фильтров, меню и галереи не создаёт long tasks и не ухудшает INP.
- [ ] Анимации появления не скрывают контент от пользователя/бота и учитывают `prefers-reduced-motion`.
- [ ] Нет layout shift при загрузке шрифтов, шапки, фотографий и фиксированной мобильной CTA.
- [ ] Статические ассеты отдаются с Brotli/Gzip и разумным `Cache-Control`; хешированные ассеты кешируются надолго.
- [ ] Общий объём, число запросов и TTFB проверены на медленном мобильном профиле.

## 7. Контент и товарные страницы

- [ ] Каждая карточка описывает именно показанный товар, а не всю интерьерную композицию.
- [ ] Название, SKU, цена, старая цена, размеры, статус и источник сверены с публикацией Well Art.
- [ ] Нет слов «демонстрационная версия», «макет», неподтверждённых характеристик и вымышленных брендов.
- [ ] У карточек достаточно уникального текста; одинаковые описания не размножаются между вариациями.
- [ ] Страницы без подтверждённой цены явно предлагают «Уточнить цену», а не публикуют фиктивную стоимость.
- [ ] Просроченные товары обрабатываются последовательно: обновление, статус «под заказ/нет в наличии», аналог либо 301 — без массового удаления полезных URL.
- [ ] Категории имеют собственный полезный вводный текст, ассортимент и внутренние ссылки, а не являются тонкими дублями каталога.
- [ ] Контактные данные едины на всех страницах.

## 8. Внутренняя перелинковка и навигация

- [ ] Все товары доступны обычными `<a href>` без обязательного выполнения JavaScript.
- [ ] Нет orphan pages: каждая индексируемая карточка связана с каталогом/категорией.
- [ ] Хлебные крошки кликабельны и совпадают с реальной иерархией.
- [ ] Блок похожих товаров не ведёт на текущий товар и не содержит битых ссылок.
- [ ] Проверить все внутренние и внешние ссылки на 4xx/5xx и цепочки редиректов.
- [ ] Ссылки WhatsApp, Telegram, Instagram, телефона и 2ГИС работают на mobile и desktop.
- [ ] Анкоры описательны; нет массовых бессмысленных «подробнее» без контекста.

## 9. Mobile, доступность и UX, влияющие на поиск

- [ ] viewport настроен корректно; нет горизонтального скролла на 320–430 px.
- [ ] Мобильное меню можно открыть и закрыть кнопкой, Escape и после перехода по ссылке; фон не перекрывает текст страницы некорректно.
- [ ] Фильтры каталога доступны с клавиатуры и не блокируют прокрутку после закрытия.
- [ ] Диалог галереи имеет доступное имя, удерживает/возвращает фокус и закрывается Escape.
- [ ] Контраст текста, состояния `:focus-visible`, размеры touch targets и логичный tab order соответствуют WCAG.
- [ ] Основной контент остаётся доступным без JS; интерактивные улучшения деградируют безопасно.

## 10. Vercel и HTTP

- [ ] HTTPS включён, сертификат валиден, нет mixed content.
- [ ] Проверены заголовки `Content-Type`, `Content-Encoding`, `Cache-Control`, `Vary` и статус для HTML/CSS/JS/изображений.
- [ ] Добавлены уместные security headers: `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP после тестирования.
- [ ] Нет случайно опубликованных исходников, временных PDF, скриншотов, секретов, `.env` и служебных файлов.
- [ ] Preview-деплои Vercel не индексируются и не конкурируют с production.
- [ ] Production-домен назначен основной ветке; старые deployment URL не используются во внутренних ссылках.
- [ ] Проверить фактический `Content-Language` необязательно, но `lang="ru"` в HTML обязателен и уже есть.

## 11. Аналитика и контроль после запуска

- [ ] Подключить Google Search Console и Яндекс Вебмастер после выбора домена.
- [ ] Отправить sitemap и проверить несколько URL инструментом проверки индексирования.
- [ ] Подключить Яндекс Метрику/аналитику только после согласования счётчика и политики конфиденциальности.
- [ ] Отслеживать клики по WhatsApp, телефону, Telegram, 2ГИС и карточкам товаров.
- [ ] Проверять 404, Web Vitals, рост индексируемых страниц и поисковые запросы после каждого крупного обновления каталога.
- [ ] Завести регламент актуальности цены/наличия и дату последней проверки товарных данных.

## 12. Инструменты для проверки

- Google Search Console: индексирование, sitemap, Core Web Vitals.
- Яндекс Вебмастер: диагностика, индексирование, региональность и sitemap.
- Google Rich Results Test: Product, Breadcrumb и Local Business.
- Schema.org Validator: полная проверка JSON-LD.
- PageSpeed Insights и Chrome Lighthouse: лабораторные и полевые показатели.

- Screaming Frog или аналог: обход URL, статусы, canonical, title, H1, метаданные, изображения и внутренние ссылки.
- WebPageTest: waterfall и реальные профили сети/устройства.
